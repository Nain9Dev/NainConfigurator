## 1. Purpose

Define the public HTTP and JSON contracts used by the 3D configurator and the ASP.NET Core API.

The contracts are product-agnostic. They use companies, products, option groups, options, compatibility rules, configurations and quote requests. They do not contain desk-specific properties.

## 2. General conventions

- Base path: `/api/v1`
- Content type: `application/json`
- Property naming: `camelCase`
- Dates: ISO 8601 UTC
- Currency codes: ISO 4217
- Language tags: BCP 47
- Prices: decimal JSON numbers
- Public requests use stable codes, never internal database identifiers.
- The client never sends an authoritative price.
- The API always validates selections and recalculates the estimated price.
- Every write use case owns one atomic transaction; the exact persistence transaction mechanism belongs to architecture.
- Product configuration is generated from catalog data; the public client and optional 3D renderer must not hardcode commercial options.
- `visualAssetKey` is client-agnostic and can be mapped by Babylon.js, Three.js or another renderer.
- `visualState` is optional presentation data and is never authoritative business data.
- Public DTOs are contracts, not database table definitions.
- Human-readable catalog, snapshot and error text uses the resolved company locale; stable codes remain language-neutral.
- Successful catalog responses expose `company.locale`, and the HTTP `Content-Language` header uses the same resolved BCP 47 value.
- Validation, configuration-create and configuration-read responses expose `contentLocale`; successful response headers use that same locale.
- When a company or saved locale can be resolved, human-readable error messages use it. Otherwise the public MVP platform default is `es-ES`; clients still use stable error codes for recovery.
- The MVP resolves one default locale per company. It does not negotiate a different language from the browser or return per-language properties.
- Entity ownership and persistence requirements are defined in `03-DataModel.md`; internal identifiers are never inferred from public codes.
- Public state-changing routes accept only UTF-8 `application/json`; compressed request bodies and unknown JSON properties are rejected.
- Validate/create configuration bodies are limited to 128 KB uncompressed; quote-create bodies are limited to 8 KB; JSON depth is limited to 16.
- Configuration and quote public codes contain at least 96 bits of cryptographic randomness.
- Application abuse limits return `429 Too Many Requests`, `RATE_LIMIT_EXCEEDED` and `Retry-After`; controlled infrastructure overload remains `503`.

## 3. Standard response envelope

### Success

```json
{
  "success": true,
  "data": {},
  "errors": [],
  "traceId": "0HN7M9F3S6K2A:00000001"
}
```

### Error

```json
{
  "success": false,
  "data": null,
  "errors": [
    {
      "code": "INVALID_OPTION_COMBINATION",
      "message": "Las patas elevables eléctricas requieren un tablero de al menos 140 x 70 cm.",
      "target": "selectedOptionCodes"
    }
  ],
  "traceId": "0HN7M9F3S6K2A:00000001"
}
```

### Error object

| Property | Type | Required | Description |
|---|---|---:|---|
| code | string | Yes | Stable machine-readable error code |
| message | string | Yes | Localized human-readable explanation; stable client recovery uses `code`, not message comparison |
| target | string | No | Request property related to the error |

## 4. Public identifiers

| Resource | Example |
|---|---|
| Company slug | `naindev-demo` |
| Product code | `DESK-001` |
| Option group code | `DESKTOP_SIZE` |
| Option code | `SIZE_160_80` |
| Configuration code | `NCF-A72F1C904B8D6E2134FA09BC` |
| Quote request code | `NQR-43C81A729D0E4B5F8612AC70` |

Internal numeric identifiers must not be returned to the public client.

Configuration codes match `^NCF-[0-9A-F]{24}$`. Quote request codes match `^NQR-[0-9A-F]{24}$`. The 24-character random portion is generated from a cryptographically strong source, codes are globally unique and immutable, and a collision is retried inside the same operation.

### Contract rules

- Only active products, option groups and options are returned.
- Option codes must be unique inside a product.
- `minSelections` and `maxSelections` define required, optional, single and multiple selection groups without desk-specific logic. A null `maxSelections` means no explicit business limit.
- The client uses `visualAssetKey` only for visual mapping.
- The API remains the authoritative validator.
- `company.locale` is the BCP 47 locale of all human-readable company and catalog content in the response. The initial MVP supports `es-ES`.
- `company.branding` may be null when no current profile is available. When present, its `version` changes independently from `catalogVersion`, `mode` is `CoBranded` in the MVP, `logoAssetKey` may be null, and both color values use validated `#RRGGBB` syntax.
- Missing or unusable branding is a presentation fallback condition; it must not change catalog availability, validation, price or saved snapshots.
- `company.privacyPolicy.activeVersion` is the 1-to-100-Unicode-scalar version that a quote request must acknowledge. `resourceUrl` is an absolute HTTPS resource of at most 2,048 Unicode scalar values that the client must present first; `contentHashSha256` identifies its exact content, `publishedAtUtc` is server authoritative and `quoteRetentionDays` is the approved 30-to-1,825-day retention value.
- `catalogVersion` must increment whenever a published change can affect the selectable interface, 3D representation, validation, price or saved snapshot. This includes:
  - Product base price, currency, name, description or availability.
  - Option group name, active state, sort order or selection limits.
  - Option name, group, active state, sort order, default state, price or `visualAssetKey`.
  - Compatibility rule type, source, targets, active state or message.
- A company display-name change also increments the version of each published product whose saved configuration snapshot includes that name.
- A company default-locale change is published with aligned catalog text and increments each affected product version because new snapshots preserve the resolved locale.
- A branding-only change does not increment `catalogVersion`; it increments `company.branding.version`.

### Published catalog capacity contract

Managed publication prevents a public catalog from exceeding:

| Value | Maximum |
|---|---:|
| Active option groups | 50 per product |
| Active options | 500 per product |
| Active compatibility rules | 500 per product |
| Active rule participant links | 2,000 per product |
| Company display name | 150 Unicode scalar values |
| Product name | 150 Unicode scalar values |
| Product description | 2,000 Unicode scalar values |
| Price disclaimer | 500 Unicode scalar values |
| Option-group name | 150 Unicode scalar values |
| Option name | 150 Unicode scalar values |
| Compatibility-rule message | 500 Unicode scalar values |
| Visual or logo asset key | 200 Unicode scalar values |

The complete uncompressed product-catalog JSON is supported up to 2 MB. These are publication constraints, not truncation instructions; a public response always returns the complete approved values.

### Possible errors

- `COMPANY_NOT_FOUND`
- `PRODUCT_NOT_FOUND`
- `PRODUCT_NOT_AVAILABLE`

### Validation rules

- The company and product must exist and be active.
- `catalogVersion` must match the current product catalog.
- Every option must exist, be active and belong to the selected product.
- Duplicate option codes are rejected.
- Each option group must satisfy its `minSelections` and `maxSelections`.
- Compatibility rules must be satisfied.
- The API recalculates the estimated price from persisted values.

## 7. Create configuration

Validates, recalculates and saves a configuration in one atomic application transaction.

### Endpoint

```http
POST /api/v1/configurations
```

### Request

```json
{
  "clientRequestId": "7d857780-a87f-44d7-9a72-9d3376941f57",
  "companySlug": "naindev-demo",
  "productCode": "DESK-001",
  "catalogVersion": 1,
  "selectedOptionCodes": [
    "SIZE_160_80",
    "FINISH_DARK_WALNUT",
    "LEG_ELECTRIC_STANDING",
    "DRAWER_RIGHT",
    "ACCESSORY_MONITOR_STAND",
    "ACCESSORY_CABLE_TRAY",
    "ACCESSORY_RGB_LIGHTING",
    "ACCESSORY_HEADPHONE_HOLDER"
  ],
  "visualState": {
    "schemaVersion": 1,
    "camera": {
      "position": {
        "x": 1.50,
        "y": 2.00,
        "z": -4.50
      },
      "rotation": {
        "x": 15.00,
        "y": 35.00,
        "z": 0.00
      }
    }
  }
}
```

### Field constraints

| Property | Rule |
|---|---|
| clientRequestId | Required GUID; unique per create attempt |
| companySlug | Required; maximum 100 characters |
| productCode | Required; maximum 50 characters |
| catalogVersion | Required; positive integer |
| selectedOptionCodes | Required; at least one item; no duplicates |
| visualState | Optional; maximum serialized size 16 KB |

When `visualState` is present:

- `schemaVersion` is required and must be `1` for the MVP.
- Version 1 accepts only the documented camera position and rotation structure.
- All camera values must be finite JSON numbers.
- A payload larger than 16 KB returns `VISUAL_STATE_TOO_LARGE`.
- A malformed payload, a missing `schemaVersion` or data outside the supported schema returns `VISUAL_STATE_INVALID`.
- A `schemaVersion` other than `1` returns `VISUAL_STATE_SCHEMA_UNSUPPORTED`.

### Success response

Status: `201 Created`

```json
{
  "success": true,
  "data": {
    "configurationCode": "NCF-A72F1C904B8D6E2134FA09BC",
    "companySlug": "naindev-demo",
    "productCode": "DESK-001",
    "catalogVersionAtCreation": 1,
    "contentLocale": "es-ES",
    "estimatedPrice": 819.90,
    "currencyCode": "EUR",
    "createdAtUtc": "2026-07-14T12:00:00Z",
    "wasExisting": false
  },
  "errors": [],
  "traceId": "0HN7M9F3S6K2A:00000001"
}
```

### Idempotent replay response

When the same `clientRequestId` is received again with the same payload, the existing configuration is returned instead of inserting a duplicate.

Status: `200 OK`

```json
{
  "success": true,
  "data": {
    "configurationCode": "NCF-A72F1C904B8D6E2134FA09BC",
    "companySlug": "naindev-demo",
    "productCode": "DESK-001",
    "catalogVersionAtCreation": 1,
    "contentLocale": "es-ES",
    "estimatedPrice": 819.90,
    "currencyCode": "EUR",
    "createdAtUtc": "2026-07-14T12:00:00Z",
    "wasExisting": true
  },
  "errors": [],
  "traceId": "0HN7M9F3S6K2A:00000001"
}
```

### Idempotency conflict

When the same `clientRequestId` is reused with a different payload, the request is rejected.

Status: `409 Conflict`

```json
{
  "success": false,
  "data": null,
  "errors": [
    {
      "code": "CLIENT_REQUEST_ID_REUSED",
      "message": "El identificador de solicitud ya se utilizó con datos diferentes.",
      "target": "clientRequestId"
    }
  ],
  "traceId": "0HN7M9F3S6K2A:00000001"
}
```

### Persistence snapshots

The saved configuration preserves:

- Company slug and name
- Product code and name
- Catalog version
- BCP 47 content locale used by all human-readable snapshot values
- Product base price
- Currency code
- Option group code and name
- Option code and name
- Option price adjustment
- Visual asset key
- Total estimated price
- Optional visual state

## 9. Create quote request

Creates a commercial contact request associated with a saved configuration.

The public resource is named `quote request`. The internal domain entity may be named `Lead`.

### Endpoint

```http
POST /api/v1/quote-requests
```

### Request

```json
{
  "clientRequestId": "e0bd8310-7e2c-4cf3-89b6-41f2e68d92dc",
  "configurationCode": "NCF-A72F1C904B8D6E2134FA09BC",
  "contact": {
    "name": "John Smith",
    "email": "john.smith@example.com",
    "phone": "+34123456789"
  },
  "message": "Me gustaría recibir un presupuesto para esta configuración.",
  "privacyPolicy": {
    "acknowledged": true,
    "version": "2026-07-14"
  }
}
```

### Field constraints

| Property | Rule |
|---|---|
| clientRequestId | Required GUID; unique per create attempt |
| configurationCode | Required; maximum 30 characters |
| contact.name | Required; maximum 150 characters |
| contact.email | Required; valid format; maximum 254 characters |
| contact.phone | Optional; maximum 30 characters |
| message | Optional; maximum 1000 characters |
| privacyPolicy.acknowledged | Must be true; records presentation only and is not marketing consent or lawful-basis selection |
| privacyPolicy.version | Required; 1-100 Unicode scalar values; must equal the active company privacy policy version |

### Success response

Status: `201 Created`

```json
{
  "success": true,
  "data": {
    "quoteRequestCode": "NQR-43C81A729D0E4B5F8612AC70",
    "configurationCode": "NCF-A72F1C904B8D6E2134FA09BC",
    "status": "New",
    "createdAtUtc": "2026-07-14T12:10:00Z",
    "retentionUntilUtc": "2027-07-14T12:10:00Z",
    "wasExisting": false
  },
  "errors": [],
  "traceId": "0HN7M9F3S6K2A:00000001"
}
```

### Idempotent replay response

When the same quote `clientRequestId` is received again with the same normalized configuration code, contact values, message and privacy acknowledgment, the existing quote request is returned without creating a second commercial action. A successful replay is resolved before current product availability and current privacy policy validation while the quote still exists inside its retention window.

Status: `200 OK`

```json
{
  "success": true,
  "data": {
    "quoteRequestCode": "NQR-43C81A729D0E4B5F8612AC70",
    "configurationCode": "NCF-A72F1C904B8D6E2134FA09BC",
    "status": "New",
    "createdAtUtc": "2026-07-14T12:10:00Z",
    "retentionUntilUtc": "2027-07-14T12:10:00Z",
    "wasExisting": true
  },
  "errors": [],
  "traceId": "0HN7M9F3S6K2A:00000001"
}
```

### Idempotency conflict

When the same quote `clientRequestId` is reused with different normalized data, the request is rejected and no second quote request is created.

Status: `409 Conflict`

```json
{
  "success": false,
  "data": null,
  "errors": [
    {
      "code": "CLIENT_REQUEST_ID_REUSED",
      "message": "El identificador de solicitud ya se utilizó con datos diferentes.",
      "target": "clientRequestId"
    }
  ],
  "traceId": "0HN7M9F3S6K2A:00000001"
}
```

### Product unavailable response

When no successful idempotent replay exists and the saved configuration's current product is inactive or unpublished, a new quote request is rejected. The historical configuration remains retrievable.

Status: `422 Unprocessable Entity`

```json
{
  "success": false,
  "data": null,
  "errors": [
    {
      "code": "PRODUCT_NOT_AVAILABLE",
      "message": "El producto configurado no está disponible para nuevas solicitudes de presupuesto.",
      "target": "configurationCode"
    }
  ],
  "traceId": "0HN7M9F3S6K2A:00000001"
}
```

### Validation rules

- An existing successful quote idempotency record is resolved before current product and privacy policy validation.
- The configuration must exist.
- For a new quote request, the product referenced by the configuration must currently be active and published.
- Contact name and email are required.
- Phone and message are optional.
- Privacy-policy acknowledgment and version are required.
- `privacyPolicy.version` must match `company.privacyPolicy.activeVersion` at submission time. A mismatch returns `PRIVACY_POLICY_VERSION_OUTDATED`; the client must reload the catalog and present the current `resourceUrl` before retrying.
- The API stores the server-side acknowledgment timestamp, policy content hash and `retentionUntilUtc` calculated from the active policy version.
- Idempotency follows the same rules as configuration creation.

## 13. Compatibility rule types

The MVP validation engine supports exactly one executable rule type:

| Type | Meaning |
|---|---|
| RequiresAny | Selecting a source option requires at least one target option |

`RequiresAll` and `ExcludesAny` are reserved for future use and must not be published as active rules until both the API and client implement and test them. An active unknown or unsupported rule type makes the affected product unavailable; it must not be silently ignored.

## 14. Future endpoints not included in the MVP

The resource structure allows these endpoints later without breaking the current contract:

```http
GET /api/v1/companies/{companySlug}/products
GET /api/v1/quote-requests/{quoteRequestCode}
```

The future quote-detail route is private and requires authenticated, company-scoped authorization; possession of `quoteRequestCode` alone never grants access. Public customer accounts, product administration and payments are outside the MVP.

## 15. Implementation order

Implement one vertical slice at a time:

1. `GET /api/v1/companies/{companySlug}/products/{productCode}`
2. `POST /api/v1/configurations/validate`
3. `POST /api/v1/configurations`
4. `GET /api/v1/configurations/{configurationCode}`
5. `POST /api/v1/quote-requests`

Validation and price calculation must be implemented once in the Application layer and reused by validation and creation operations.
